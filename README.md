# Palette-Swap

Minecraftテクスチャ編集用のWindowsデスクトップアプリです。Electronで起動し、PNGやZIPを保存ダイアログから出力できます。

アプリの左側に素材ライブラリがあり、同梱のMinecraftテクスチャ全体（ブロック、アイテム、エンティティ、GUIなど）を検索して編集できます。選んだ画像は16×16に合わせて読み込み、透明部分を保ちながら最大11色に整理します。素材一覧は表示を軽くするため一度に最大250件まで表示し、検索やカテゴリで絞り込めます。

ヘルメット・チェストプレート・レギンス・ブーツなどの防具は、素材ライブラリに素材ごとの画像を個別に表示します。選んだ防具の実際の画像を編集し、PNGまたはZIPで保存できます。革・チェーン・鉄・金・ダイヤ・ネザライトに加えて、素材がある銅防具やカメのヘルメットも表示します。画像を自動色抽出で取り込んでも、取込専用の素材が一覧に増え続けることはありません。元画像の色に合わせる場合は、読み込み時の「選択中の素材の色に合わせる」を選んでください。

画面はWindowsアプリのメニューバー、左の縦型ツールバーと素材パネル、中央のアートボード、右のカラー・素材・レイヤーパネルに分かれています。左上のアプリアイコンには同梱の `favicon.ico` を使用します。ツールバー・素材パネル・右パネルの境界をドラッグすると幅を調整でき、設定は次回起動後も保持されます。境界を選択して左右矢印キーで調整し、ダブルクリックまたはHomeキーで初期幅に戻せます。右上の「保存 / 書き出し」から、作業中の全タブとカスタム素材を独自形式の `.psproj` ファイルに保存・読み込みできます。保存した `.psproj` はアプリをアンインストールしても残る場所に保管し、再インストール後に開いて作業を続けられます。WindowsでPaletteSwapがインストールされていれば、`.psproj` をダブルクリックして開くこともできます。PNGやZIPの書き出しも同じメニューから行えます。アイテム名とpack_formatは右側のエクスポート設定で指定します。ツール設定、テンプレート、PNG読み込みは素材パネル上部にあります。素材一覧には各テクスチャのプレビューが表示され、防具・剣・つるはし・斧・シャベル・クワなど種類ごとに分類されます。通常アイテムの素材違いは一覧上で重複表示せず、各セットの編集画面で切り替えます。防具は素材ごとの画像を個別に選択できます。テクスチャを選ぶと編集タブが開き、複数の画像を切り替えて編集できます。新規タブボタンで空のテクスチャを開き、各タブの×ボタンで閉じられます。タブごとに画像、色、選択範囲、ツール、Undo/Redo履歴を保持します。

このソフトはWindowsデスクトップアプリ専用です。ブラウザーでHTMLを直接開いた場合は起動せず、インストーラーからPalette-Swapを起動してください。

羊毛、カーペット、コンクリート、テラコッタ、色付きガラス、ベッド、ろうそくなど、既知の色違いブロックは色別のバリエーションとしてまとめて編集できます。「ピクセル編集を同期」をオフにすると、各素材・色のテクスチャを個別に編集でき、編集内容とUndo/Redo履歴も種類ごとに保持されます。同期を再びオンにすると、選択中の種類の編集内容がほかの種類にも反映されます。パンなど素材違いのない画像は「単一画像のカラー」として1種類だけを編集・保存します。剣やツール、防具などは素材違いの画像が存在する場合だけ、その素材を一覧に表示します。選択範囲のコピー・切り取り・反転などの操作は左側のツール欄にあります。ZIP出力は元のテクスチャのカテゴリ（block/itemなど）に合わせたパスで保存します。

## 開発起動

Node.jsをインストールした後、プロジェクトのフォルダーで実行します。

```powershell
npm install
npm start
```

## Windowsインストーラー作成（ローカル確認用）

```powershell
npm install
npm run dist:win
```

作成されたインストーラーは `dist` フォルダーに出力されます。このコマンドはローカルでインストーラーを作るだけで、GitHub Releasesには公開しません。

## Windows版のリリースと自動更新

配布先は [GitHub Releases](https://github.com/sirotumekuma/PaletteSwap/releases) です。普段のリリース作業は「変更をPush」「バージョンを上げてタグを作成」「タグをPush」の3段階です。タグをPushするとGitHub ActionsがWindows版をビルドしてReleaseに公開します。

### いつものリリース手順

PowerShellでプロジェクトのフォルダーを開いて作業します。最初にアプリの変更をコミットしてGitHubへPushしてください。`npm version` は作業中の変更を含めてバージョンコミットを作成するため、未コミットの変更がない状態にしてから実行します。

```powershell
# 1. アプリの変更をコミットしてPush（変更内容に合わせてファイルを指定）
git add <変更したファイル>
git commit -m "変更内容を入力"
git push origin main

# 2. パッチバージョンを上げる（例: 1.0.10 → 1.0.11）
# package.json と package-lock.json を更新し、コミットと v1.0.11 タグを作成
npm version patch

# 3. バージョンコミットとタグをGitHubへPush
git push origin main --follow-tags
```

これで公開処理が始まります。機能追加などで番号の上げ方を変えたい場合は、`npm version minor`（例: 1.0.10 → 1.1.0）または `npm version major`（例: 1.0.10 → 2.0.0）を使います。バージョン番号は`package.json`の値から自動で更新されるので、タグ名やRelease本文を手入力する必要はありません。

### 公開されたか確認する

1. GitHubリポジトリの **Actions** タブを開き、`Release Windows app` の実行が成功（緑のチェック）したことを確認します。タグは`v1.2.3`の形式にし、タグの数字と`package.json`の`version`を一致させてください。一致していない場合、Actionsはインストーラーを作る前にエラーを表示します。
2. [GitHub Releases](https://github.com/sirotumekuma/PaletteSwap/releases)を開き、新しいバージョンが表示されていることを確認します。Releaseには `PaletteSwap-Setup-<バージョン>.exe`、`latest.yml`、`.blockmap` が添付されます。
3. 利用者に案内するのは `PaletteSwap-Setup-<バージョン>.exe` だけです。`latest.yml` と `.blockmap` は自動更新に必要なファイルなので、手動でダウンロード・配布する必要はありません。

GitHub Actionsが失敗した場合は、Actionsの実行を開き、赤い×のステップをクリックしてエラーを確認します。`Verify tag matches app version`で失敗した場合は、`package.json`のバージョンとタグ名を一致させてください。古いワークフローで`Validation Failed: already_exists (tag_name)`が出た場合は、Release作成時の競合が原因です。最新のワークフローを`main`にPushした後、下記の「既存Releaseの修復」を実行してください。

このワークフローは最初にインストーラーをローカルでビルドし、その後GitHub CLIで`.exe`、`.blockmap`、`latest.yml`を順番にReleaseへアップロードします。これにより、ビルドツールがReleaseを同時に作成して`already_exis　ts (tag_name)`になる競合を避けます。GitHub APIでReleaseの存在を確認し、既存の場合はアセットを上書きして修復します。Release本文も同じ処理で設定します。

### 既存Releaseの修復

Releaseページはあるのに`.exe`や`latest.yml`がない場合は、同じバージョンを新しく作る必要はありません。修正版のワークフローを`main`へPushした後、GitHubの **Actions** タブから次の手順で既存Releaseを修復します。

1. 左側で`Release Windows app`を選び、**Run workflow**を押します。
2. ブランチは`main`を選択し、`release_tag`に修復するタグを入力します（例: `v1.0.13`）。
3. **Run workflow**を押し、実行が成功するまで待ちます。
4. 対応するReleaseを開き、`.exe`、`.blockmap`、`latest.yml`が添付されたことを確認します。

この手動実行では、指定タグのソースを使ってビルドし、既存Releaseのファイルを上書きします。`release_tag`とそのタグ内の`package.json`のバージョンが一致している必要があります。GitHub ActionsのNode.js 20警告が表示された場合は、`main`に最新の`release-windows.yml`がPush済みかを確認してください。権限エラーの場合は、リポジトリの **Settings > Actions > General > Workflow permissions** で、ワークフローにContentsの書き込みを許可します。

### 利用者側の更新方法

Releaseが公開されると、インストーラー版のPaletteSwapは起動時に更新を確認し、新版を自動でダウンロードします。画面上部に「再起動して更新」と表示されたら、そのボタンを押すと更新が適用されます。すぐに更新したい場合は「更新を確認」を押してください。自動更新はインストーラー版で利用できます。開発版や`dist`フォルダーに作っただけの`.exe`は、GitHub Releaseへ公開されていないため自動更新されません。

`npm run dist:win` はローカル確認用のインストーラーを`dist`フォルダーに作るコマンドです。GitHubへ公開するときは、上記の手順でバージョンタグをPushしてください。個人アクセストークンを作成する必要はありません。Actionsがリポジトリの`GITHUB_TOKEN`を使って公開します。
