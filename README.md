# Palette-Swap

Minecraftテクスチャ編集用のWindowsデスクトップアプリです。Electronで起動し、PNGやZIPを保存ダイアログから出力できます。

アプリの左側に素材ライブラリがあり、同梱のMinecraftテクスチャ全体（ブロック、アイテム、エンティティ、GUIなど）を検索して編集できます。選んだ画像は16×16に合わせて読み込み、透明部分を保ちながら最大11色に整理します。素材一覧は表示を軽くするため一度に最大250件まで表示し、検索やカテゴリで絞り込めます。

ヘルメット・チェストプレート・レギンス・ブーツなどの防具は、素材ライブラリに素材ごとの画像を個別に表示します。選んだ防具の実際の画像を編集し、PNGまたはZIPで保存できます。革・チェーン・鉄・金・ダイヤ・ネザライトに加えて、素材がある銅防具やカメのヘルメットも表示します。画像を自動色抽出で取り込んでも、取込専用の素材が一覧に増え続けることはありません。元画像の色に合わせる場合は、読み込み時の「選択中の素材の色に合わせる」を選んでください。

画面はWindowsアプリのメニューバー、左の縦型ツールバーと素材パネル、中央のアートボード、右のカラー・素材・レイヤーパネルに分かれています。左上のアプリアイコンには同梱の `favicon.ico` を使用します。ツールバー・素材パネル・右パネルの境界をドラッグすると幅を調整でき、設定は次回起動後も保持されます。境界を選択して左右矢印キーで調整し、ダブルクリックまたはHomeキーで初期幅に戻せます。右上の「エクスポート」から選択中の素材をPNG、または全素材をZIPで出力できます。アイテム名とpack_formatは右側のエクスポート設定で指定します。ツール設定、テンプレート、PNG読み込みは素材パネル上部にあります。素材一覧には各テクスチャのプレビューが表示され、防具・剣・つるはし・斧・シャベル・クワなど種類ごとに分類されます。通常アイテムの素材違いは一覧上で重複表示せず、各セットの編集画面で切り替えます。防具は素材ごとの画像を個別に選択できます。テクスチャを選ぶと編集タブが開き、複数の画像を切り替えて編集できます。新規タブボタンで空のテクスチャを開き、各タブの×ボタンで閉じられます。タブごとに画像、色、選択範囲、ツール、Undo/Redo履歴を保持します。

このソフトはWindowsデスクトップアプリ専用です。ブラウザーでHTMLを直接開いた場合は起動せず、インストーラーからPalette-Swapを起動してください。

羊毛、カーペット、コンクリート、テラコッタ、色付きガラス、ベッド、ろうそくなど、既知の色違いブロックは色別のバリエーションとしてまとめて編集できます。「ピクセル編集を同期」をオフにすると、各素材・色のテクスチャを個別に編集でき、編集内容とUndo/Redo履歴も種類ごとに保持されます。同期を再びオンにすると、選択中の種類の編集内容がほかの種類にも反映されます。パンなど素材違いのない画像は「単一画像のカラー」として1種類だけを編集・保存します。剣やツール、防具などは素材違いの画像が存在する場合だけ、その素材を一覧に表示します。選択範囲のコピー・切り取り・反転などの操作は左側のツール欄にあります。ZIP出力は元のテクスチャのカテゴリ（block/itemなど）に合わせたパスで保存します。

## 開発起動

Node.jsをインストールした後、プロジェクトのフォルダーで実行します。

```powershell
npm install
npm start
```

## Windowsインストーラー作成（ローカル確認用）

```powershell
npm install
npm run dist:win
```

作成されたインストーラーは `dist` フォルダーに出力されます。このコマンドはローカルでインストーラーを作るだけで、GitHub Releasesには公開しません。

## Windows版のリリースと自動更新

配布先は [GitHub Releases](https://github.com/sirotumekuma/PaletteSwap/releases) です。`dist:win` はインストーラーをPC内の `dist` フォルダーに作るだけで、GitHubには公開しません。GitHub Actionsで公開するには、次の手順で新しいバージョンのタグをPushします。

1. 変更をコミットしてGitHubにPushします。
2. `package.json` と `package-lock.json` のバージョンを、公開済みの最新バージョンより大きい未使用の番号に上げます。パッチバージョンを上げる場合は次のコマンドを使えます。

   ```powershell
   npm version patch --no-git-tag-version
   ```

3. バージョン変更をコミットしてGitHubにPushします。
4. `package.json` と同じバージョンのタグを作成してPushします。たとえばバージョンが `1.0.9` の場合は次のとおりです。

   ```powershell
   git tag v1.0.9
   git push origin v1.0.9
   ```

5. GitHubの **Actions** で `Release Windows app` が成功したことを確認します。成功すると [GitHub Releases](https://github.com/sirotumekuma/PaletteSwap/releases) に `PaletteSwap-Setup-<バージョン>.exe`、`latest.yml`、`.blockmap` が公開され、リリース説明もバージョンに合わせて設定されます。

このワークフローはリポジトリの `GITHUB_TOKEN` を使ってリリースを作成するため、個人アクセストークンを発行・保存する必要はありません。Actionsの実行が権限エラーになる場合は、GitHubリポジトリの **Settings > Actions > General > Workflow permissions** で、ワークフローにContentsの書き込みを許可してください。

アプリの自動更新は、インストーラー版が公開済みReleaseの `latest.yml` を確認して行います。ビルドしただけの `.exe` や、GitHubにPushしただけのソースコードは更新対象になりません。Releaseの公開後、インストール済みアプリは起動時に更新を確認して新版をダウンロードします。準備ができたら、画面上部の「再起動して更新」を押してください。開発版や `dist` 内のインストーラーでは自動更新されません。
